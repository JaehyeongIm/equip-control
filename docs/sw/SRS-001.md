## 1. 목적 및 적용 범위

본 문서는 챔버 온도 제어 시스템의 소프트웨어 요구사항을 정의한다. 대상 소프트웨어는 두 계층이다.

| 계층 | 명칭 | 구현 환경 |
|------|------|---------|
| FW | Firmware | STM32F446RE, C, FreeRTOS 10.3.1 |
| EC | Host Monitor (호스트 모니터) | macOS, Python 3 |

## 3. 용어 정의

| 용어 | 정의 |
|------|------|
| SP | 온도 설정점 (Setpoint) |
| ALARM | 히터 강제 차단이 수반되는 중대 이상 상태 |
| WARNING | 히터 유지, 팬 냉각으로 복귀 유도하는 경미 이상 상태 |
| RESET | 알람 해제 및 IDLE 복귀 명령 |
| Duty | 히터 PWM 듀티비 (0.0 ~ 100.0%) |
| KPI | 핵심 성능 지표 (도달 시간, 오버슈트, 안정화 시간) |

## 5. 기능 요구사항 — FW

### 5.1 온도 측정

| 요구사항 ID | 요구사항 내용 | 우선순위 |
|-----------|------------|---------|
| REQ-F-001 | 챔버 내부 온도를 DHT22로 2s 주기로 측정한다 | 필수 |
| REQ-F-002 | DHT22 읽기 실패가 3회 연속 발생하면 센서 오류로 판정한다 | 필수 |
| REQ-F-003 | 센서 오류 판정 시 즉시 히터를 OFF하고 ALARM 상태로 진입한다 | 필수 |

### 5.2 히터 제어

| 요구사항 ID | 요구사항 내용 | 우선순위 |
|-----------|------------|---------|
| REQ-F-004 | PI 알고리즘(Kp=200, Ki=2)으로 히터 PWM을 제어하여 설정 온도(SP)를 유지한다 | 필수 |
| REQ-F-005 | 히터 출력은 TIM3_CH3(PB0, 1kHz PWM, Compare 0~1000)으로 구동한다 | 필수 |
| REQ-F-006 | ALARM 진입 시 히터 PWM을 즉시 0%로 설정하고 적분항을 초기화한다 | 필수 |

### 5.3 알람 판정

| 요구사항 ID | 요구사항 내용 | 우선순위 |
|-----------|------------|---------|
| REQ-F-007 | 온도 > SP + warn_thr(1°C) 조건이 warn_dur(5s) 지속되면 WARNING(ALM-01)으로 전이한다 | 필수 |
| REQ-F-008 | WARNING 중 온도 ≤ SP + warn_thr로 복귀하면 자동으로 HEATING으로 전이한다 | 필수 |
| REQ-F-009 | 온도 > SP + alarm_thr(2°C) 조건이 alarm_dur(10s) 지속되면 ALARM(ALM-02)으로 전이한다 | 필수 |
| REQ-F-010 | ALARM 상태에서 온도 ≤ SP − reset_thr(2°C) 조건이 충족된 경우에만 EC RESET 명령을 수락한다 | 필수 |
| REQ-F-011 | RESET 조건 미충족 시 `NACK:RESET,TEMP_HIGH`를 반환하고 상태를 유지한다 | 필수 |

### 5.4 액추에이터 제어

| 요구사항 ID | 요구사항 내용 | 우선순위 |
|-----------|------------|---------|
| REQ-F-012 | WARNING 상태에서 냉각팬을 ON하고, HEATING 복귀 또는 STOP 시 OFF한다 | 필수 |
| REQ-F-013 | ALARM 상태에서 냉각팬을 ON하고 부저를 연속 ON한다 | 필수 |
| REQ-F-014 | WARNING 상태에서 부저를 1s ON / 1s OFF 간헐 패턴으로 구동한다 | 필수 |

### 5.5 UART 통신 — FW 송신

| 요구사항 ID | 요구사항 내용 | 우선순위 |
|-----------|------------|---------|
| REQ-F-015 | 1초 주기로 DATA 프레임을 EC로 전송한다 (온도, SP, 상태, 알람, Duty, KPI 포함) | 필수 |
| REQ-F-016 | 알람 발생/해제 등 이벤트 발생 시 즉시 EVENT 메시지를 전송한다 | 필수 |
| REQ-F-017 | 명령 수락 시 `ACK:<cmd>`, 거부 시 `NACK:<cmd>,<reason>`을 반환한다 | 필수 |

### 5.6 UART 통신 — FW 수신

| 요구사항 ID | 요구사항 내용 | 우선순위 |
|-----------|------------|---------|
| REQ-F-018 | EC로부터 SET, START, STOP, RESET, STATUS 명령을 수신하고 처리한다 | 필수 |
| REQ-F-019 | SET 명령으로 SP를 20°C ~ 80°C 범위 내에서 변경한다 | 필수 |

## 6. 기능 요구사항 — EC

| 요구사항 ID | 요구사항 내용 | 우선순위 |
|-----------|------------|---------|
| REQ-EC-001 | FW로부터 수신한 DATA를 파싱하여 온도, 상태, KPI를 화면에 실시간 표시한다 | 필수 |
| REQ-EC-002 | WARNING/ALARM 발생 시 알람 패널(알람명, 원인, 복구 조건)을 표시한다 | 필수 |
| REQ-EC-003 | ALARM 상태에서 복구 조건 충족 여부(온도 ≤ SP−2°C)를 실시간 표시한다 | 필수 |
| REQ-EC-004 | 수신 데이터를 CSV 파일로 자동 로깅한다 | 권장 |

## 7. 소프트웨어 아키텍처 요구사항 (FW)

| 요구사항 ID | 요구사항 내용 | 우선순위 |
|-----------|------------|---------|
| REQ-SW-001 | FreeRTOS CMSIS-RTOS V2를 기반으로 멀티태스크 구조로 구현한다 | 필수 |
| REQ-SW-002 | 각 태스크는 담당 기능을 단독으로 수행하며, 우선순위 기반 선점형 스케줄링으로 동작한다 | 필수 |
| REQ-SW-003 | 공유 상태(g_state, 온도, KPI 등)는 Mutex로 상호배제를 보장한다 | 필수 |
| REQ-SW-004 | DHT22 읽기 중 타이밍 무결성을 위해 태스크 선점을 금지한다 | 필수 |
| REQ-SW-005 | UART TX는 단일 큐(TX Queue)를 통해 직렬화하여 HAL 중복 호출을 방지한다 | 필수 |

## 8. 비기능 요구사항

| 요구사항 ID | 요구사항 내용 | 측정 기준 |
|-----------|------------|---------|
| REQ-NF-001 | WARNING/ALARM 조건 충족 후 FW 대응(히터 OFF, 팬 ON) 완료까지 3s 이내 | TC-02, TC-03 |
| REQ-NF-002 | 히터 제어 주기는 DHT22 측정 완료 시점에 동기화된다 (최대 지연 2s + 측정 시간) | SDD-001 §4 |
| REQ-NF-003 | EC 명령에 대한 FW 응답은 1초 이내 | TC-05 |
| REQ-NF-004 | FreeRTOS Heap 사용량은 configTOTAL_HEAP_SIZE(8192B) 미만 | 정적 분석 |

## 1. 목적 및 적용 범위

본 문서는 챔버 과온 알람 진단 및 안전 복구 시스템 FW의 소프트웨어 설계를 기술한다. 설계 근거, RTOS 태스크 구조, 모듈 구성, 주요 알고리즘, UART 프로토콜 설계를 포함한다.

## 4. RTOS Task 구조도

### 4.1 태스크 구성

```
 osKernelStart()
 │
 ├─[AboveNormal]─ UartRxTask ────────────────────────────────────────┐
 │                │ ulTaskNotifyTake(100ms)                           │
 │                │ ← vTaskNotifyGiveFromISR (USART2 IRQ)            │
 │                │ osMutexAcquire → handle_cmd() → osMutexRelease   │
 │                │ uart_enqueue(ACK/NACK)                           │
 │                └───────────────────────────────────────────────── │
 │                                                                    │
 ├─[Normal]─────── SensorTask ──────────────────────────────────────┐│
 │                │ osDelay(2000ms)                                  ││
 │                │ vTaskSuspendAll()                                ││
 │                │ DHT22_Read()   ← 선점 금지 (타이밍 보호)         ││
 │                │ xTaskResumeAll()                                 ││
 │                │ osMutexAcquire → g_temp/g_temp_valid 갱신        ││
 │                │ osMutexRelease                                   ││
 │                │ osSemaphoreRelease(g_sensor_sem)                 ││
 │                └──────────────────────────────┬─────────────────────┘│
 │                                               │                  │
 ├─[AboveNormal]─ ControlTask ──────────────────┘                  │
 │                │ osSemaphoreAcquire(g_sensor_sem)                │
 │                │ osMutexAcquire                                  │
 │                │   pid_update() → heater_set()                  │
 │                │   KPI 계산 (도달 시간 / 오버슈트 / 안정화)      │
 │                │   알람 판정 (WARNING / ALARM)                   │
 │                │   팬 릴레이 직접 제어                           │
 │                │ osMutexRelease                                  │
 │                │ uart_enqueue(EVENT)                             │
 │                └──────────────────────────────┬─────────────────┘
 │                                               │ osMessageQueuePut
 ├─[Normal]─────── UartTxTask ──────────────────┘
 │                │ osMessageQueueGet(timeout=1s)
 │                │  메시지 수신: HAL_UART_Transmit(msg)
 │                │  1s 타임아웃: osMutexAcquire
 │                │              build_data_str() → HAL_UART_Transmit
 │                │              osMutexRelease
 │                └─────────────────────────────────────────────────
 │
 └─[BelowNormal]─ ActuatorTask
                  │ osDelay(50ms)
                  │ osMutexAcquire → g_state 읽기 → osMutexRelease
                  │ 부저 GPIO (ALARM=연속, WARNING=1s 토글, else=OFF)
                  └─ LED GPIO  (IDLE=OFF, HEATING=ON, else=점멸)
```

### 4.2 태스크 명세표

| 태스크 | 우선순위 | 스택(bytes) | 활성화 조건 | 주요 책임 |
|--------|---------|-----------|-----------|---------|
| SensorTask | Normal (24) | 512 | osDelay 2s | DHT22 읽기, 센서 오류 판정 |
| ControlTask | AboveNormal (25) | 1536 | g_sensor_sem | PI 제어, KPI, 알람 판정, 팬 제어 |
| UartRxTask | AboveNormal (25) | 768 | TaskNotification | 명령 수신 및 파싱, 상태 전이 |
| UartTxTask | Normal (24) | 1024 | TX Queue / 1s 타임아웃 | DATA 주기 전송, 이벤트 즉시 전송 |
| ActuatorTask | BelowNormal (23) | 384 | osDelay 50ms | 부저·LED GPIO 패턴 구동 |

### 4.3 RTOS 오브젝트 명세표

| 오브젝트 | 종류 | 크기/설정 | 생산자 | 소비자 | 보호 대상 |
|---------|------|---------|------|------|---------|
| g_state_mutex | osMutex | — | — | 모든 태스크 | g_state, g_temp, KPI 등 공유 상태 전체 |
| g_sensor_sem | osSemaphore | max=1, init=0 | SensorTask | ControlTask | DHT22 읽기 완료 신호 |
| g_tx_queue | osMessageQueue | 8 × 128B | 모든 태스크 | UartTxTask | UART 송신 문자열 |
| g_uart_rx_task_h | TaskHandle | — | ISR(USART2) | UartRxTask | 수신 라인 완성 신호 |

## 5. 모듈 설계

### 5.1 main.c

| 함수/태스크 | 역할 |
|-----------|------|
| `SensorTask` | DHT22 읽기 + 센서 오류 판정. vTaskSuspendAll로 40비트 수신 중 선점 방지 |
| `ControlTask` | PI 제어, KPI 추적, 알람 판정. g_sensor_sem으로 SensorTask와 동기화 |
| `UartRxTask` | vTaskNotifyGiveFromISR 기반 명령 수신. handle_cmd로 상태 전이 |
| `UartTxTask` | TX Queue 기반 송신 직렬화. 1s 타임아웃 시 주기 DATA 전송 |
| `ActuatorTask` | 50ms 주기 부저/LED GPIO 제어. 상태를 mutex로 읽어 패턴 결정 |
| `pid_update` | PI 제어 출력 계산. 적분 클램프 ±100, 출력 클램프 0~1000 |
| `handle_cmd` | START/STOP/RESET/SET/STATUS 명령 처리. g_state_mutex 보유 상태에서 호출 |
| `build_data_str` | DATA 프레임 문자열 생성. g_state_mutex 보유 상태에서 호출 |
| `uart_enqueue` | TX Queue에 메시지 추가 (큐 가득 시 드롭, 비차단) |
| `HAL_UART_RxCpltCallback` | 1바이트 수신 ISR. 줄 완성 시 vTaskNotifyGiveFromISR 호출 |

### 5.2 dht22.c

DHT22 단선 프로토콜 드라이버. DWT 사이클 카운터 기반 µs 딜레이 사용.

| 함수 | 역할 |
|------|------|
| `DHT22_Init` | DWT 사이클 카운터 활성화 |
| `DHT22_Read` | 40비트 수신. 시작 신호(1ms LOW) → 응답 대기 → 비트 샘플링 → 체크섬 검증 |

## 6. 핵심 알고리즘 설계

### 6.1 PI 제어

```
e(t)   = SP - T_measured
I(t)   = clamp(I(t-1) + e(t) × dt, −100, +100)
u(t)   = clamp(Kp × e(t) + Ki × I(t), 0, 1000)
```

- **dt**: DHT22 읽기 완료 간격 (약 2s, 측정 완료 시점에 갱신)
- **출력 u(t)**: TIM3_CH3 Compare 레지스터 값 (0~1000 → 0.0%~100.0%)
- **적분 클램프 ±100**: 위치 오차가 큰 상황에서 적분 폭주 방지
- **ALARM 진입 시**: heater_off() 호출로 u=0 강제 및 I, prev_err 초기화

### 6.2 알람 상태 전이 조건

```
HEATING ──[over≥WARN_THR, 타이머≥WARN_DUR]──► WARNING
WARNING ──[over<WARN_THR]──────────────────► HEATING  (자동 해제)
HEATING/WARNING ──[over≥ALARM_THR, 타이머≥ALARM_DUR]──► ALARM
ANY ──[DHT22 연속 3회 실패]───────────────► ALARM (ALM-03)
ALARM ──[EC RESET + 온도≤SP-2°C]──────────► IDLE
```

### 6.3 DHT22 타이밍 보호

```
SensorTask:
  osDelay(2000)         // 2s 대기 (선점 허용)
  vTaskSuspendAll()     // 스케줄러 일시 정지 (인터럽트는 유지)
  DHT22_Read()          // ~5ms 단선 프로토콜 (40비트 DWT 폴링)
  xTaskResumeAll()      // 스케줄러 재개
```

`vTaskSuspendAll()` 사용으로 DWT 타이밍 루프 중 다른 태스크의 선점을 방지하면서, TIM14 IRQ(HAL_Delay 1ms 내부 사용)와 USART2 IRQ는 정상 동작한다.

## 7. UART 프로토콜 설계

### 7.1 물리 계층

- 속도: 115200 bps, 8N1
- 경로: ST-LINK USB VCP → USART2 (PA2 TX / PA3 RX)

### 7.2 프레임 설계 원칙

- ASCII 텍스트, `\r\n` 종단
- 1바이트씩 ISR 수신 → 줄 완성 시 UartRxTask 알림
- TX는 TX Queue를 통해 UartTxTask가 단독 전송 (HAL 중복 호출 방지)

### 7.3 메시지 우선순위

| 종류 | 경로 | 우선순위 |
|------|------|---------|
| EVENT (알람 발생/해제) | uart_enqueue → TX Queue | 큐 순서 (선입선출) |
| ACK/NACK | uart_enqueue → TX Queue | 큐 순서 |
| DATA (주기) | 1s 타임아웃 직접 전송 | TX Queue 비어 있을 때 |

이벤트 메시지가 큐에 있으면 주기 DATA보다 먼저 전송된다.

## 8. 공유 상태 보호 설계

### 8.1 g_state_mutex 보유 범위

| 호출처 | mutex 획득 | 보호 대상 |
|--------|----------|---------|
| SensorTask | DHT22 결과 쓰기 | g_temp, g_temp_valid, g_sensor_fail |
| ControlTask | PI/알람 처리 전체 | g_state, g_integral, g_heater_cmp, KPI |
| UartRxTask | handle_cmd 실행 | g_state, g_sp, g_run_active 등 |
| UartTxTask | build_data_str 읽기 | g_state, g_temp, KPI 등 (읽기 전용) |
| ActuatorTask | g_state 읽기 | g_state (읽기 전용, 즉시 해제) |

### 8.2 설계 제약

- `uart_enqueue`는 mutex를 사용하지 않는다 (osMessageQueuePut은 내부적으로 안전).
- `heater_off`, `heater_set`은 mutex 보유 상태에서만 호출한다.
- HAL GPIO 쓰기(팬, 부저)는 BSRR 레지스터 원자 연산이므로 mutex 없이도 안전하다.
  단, 부저/LED는 ActuatorTask가 단독 관리하여 경쟁을 구조적으로 제거한다.
